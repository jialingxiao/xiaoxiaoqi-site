药学服务开始单独收费：4类10项全国落地，药学门诊6-16元一次

11 月 25 日，国家医保局披露：2026 年 2 月正式印发的《药学类医疗服务价格项目立项指南（试行）》，设立药学诊查、药品集中配置、药物浓度测定、中药药学服务等 4 类 10 项价格项目，截至目前全国各省份已全部完成对接落地。这件事的背景是药品零加成之后，医院药学部门长期处在一个尴尬位置：审方、调方、用药教育、血药浓度监测都是专业活，但没有对应的收费编码，人力成本只能摊进药事管理费里。指南给药学服务单独开了一本「明白账」，明确相关服务项目的具体内容、计价单元，既让专业价值看得见，也划清医疗服务收费边界、减少收费争议。

价格水平给得很具体。中药配方颗粒调剂费各地普遍在2-4 元/付；门诊诊查费（药学门诊）6-16 元/次，副主任（中）药师加收 5-10 元/次，主任（中）药师加收 10-15 元/次；肠内营养液药品配置费各地集中在35-40 元左右，危害药品药品配置费各地集中在30 元左右。对实际操作确有差异的特殊项目予单独立项，包括「药品集中配置费（危害药品）」「药品集中配置费（肠外营养液）」「放射性药物配置费」。指南还特别关注临床场景从以医院为中心向以患者为中心的变化，新增「居家药学服务费」等项目。一条容易被忽略的边界是：普通静脉药物配置作为医院提供注射、输液时的应尽事项，已纳入相关「注射费」的价格构成，不再单独收费。

中药侧单独成章。中药临方加工、煎煮是体现中医辨证施治的关键环节，指南规范设立中药临方加工费、中药代煎服务费；同时为配套中药配方颗粒零差率政策，明确设立中药配方颗粒调剂费，合理体现处方审核、配方调剂等技术劳务价值，实现药品价格与服务价值分开核算、透明收费。定价原则是「平移为主、结构优化」，各省参照立项指南整合规范原有项目、制定全省统一的价格基准，再指导各统筹地区具体定价，并结合经济社会发展、患者负担能力、医院运转状况、医保基金运行等因素确定水平。国家医保局表示，下一步将持续跟踪各地执行效果，更好发挥价格政策的引导与激励作用。

文心5.5 Flash Preview开源：2800亿参数只激活140亿，100万上下文

11 月 24 日，百度宣布文心 5.5 Flash Preview（ERNIE 5.5 Flash Preview）正式开源，采用 Apache 2.0 协议，模型权重与配套资源上架 Hugging Face 和 ModelScope，支持 vLLM、SGLang 等主流推理框架。参数上采用 MoE 架构，总参数 2800 亿、每个 Token 激活 140 亿，支持最长 100 万 Token 上下文，官方定位编程、3D 建模、知识工作与内容创作。该模型 11 月 11 日首次发布，基于 11 月 5 日已开源的文心 5.5 Flash Base 做后训练，此次 Preview 权重跟进开放，让这一系列从基座到后训练形成完整开放链条，前后约三周。基准测试是一条不均衡的曲线：偏 Agent 与业务流自动化的 AutomationBench 得 61.9 分，高于 Claude Opus 5.5 的 58.0 和 DeepSeek V4.1 Flash 1017 的 57.2；Terminal-Bench 4.0 得 46.5，低于 Claude Opus 5.5 的 63.6 与 GPT-6.1 Sol 的 56.1，但高于 DeepSeek V4.1 Flash 的 40.9；CodeArena WebDev 以 1668 分位列开源模型第二、国产模型第四，略高于 DeepSeek-V4.1-Flash 的 1664 与 Kimi K3 的 1658，接近 Qwen3.8-Max 的 1670。生成速度官方数据为每秒超 200 Token。值得留意的是协议选择：11 月 5 日开源的 Base 用的是自定义协议，不适用于欧盟、英国和韩国，相关产品或服务年收入超 5000 万美元的企业商用前须获百度书面授权；此次 Preview 回归了 Apache 2.0。

5.93GB装下27B模型：三值量化把工具调用精度做到FP16的99.4%

11 月 24 日，Prism ML 以 Apache 2.0 协议开源 Ternary Bonsai 2.5 27B，把一个源自 Qwen3.8-27B 的多模态推理模型压进 5.93 GB、每权重 1.76 bit。它的定位是本地长程 Agent 工作流，覆盖 macOS（Metal）、Linux 与 Windows（CUDA、Vulkan、ROCm、CPU），Q2_0 权重可在上游 llama.cpp b11556 及以上版本直接运行，无需定制分支。效果上，在五个 agentic 工具调用基准上平均 77.2 分，对照 FP16 基线 77.7 分；agentic coding 保留 FP16 的 90%，上一代 Bonsai 2 只有 63%。能力项从 Bonsai 2 延续：截图与 PDF 视觉输入、OpenAI 兼容的 tool_calls、MCP client 支持、默认 xhigh 推理预算、262k token 混合注意力上下文。每个 GGUF 内置多 Token 预测（MTP）draft head，在 NVIDIA GPU 上自动启用，带来 1.5-1.8 倍无损解码加速。三种权重布局按硬件瓶颈区分：Q2_0 走标准上游链路，PTQ1_0 走 CUDA 最快解码，PQ2_0 多花约 1.3 GB 内存换更快 prompt 预填、是官方 demo 默认下载。这套规格的意义是：接近 FP16 的 27B 函数调用、视觉与 262k 上下文塞进 5.9 GB，让开发者在常规 8 GB 与 16 GB 消费级笔记本上跑本地编码与 MCP 工具 Agent。Prism ML 尚未公布托管云 API 价格。

用印地语问农事，AI去查英文手册：IBM把跨语言语音检索跑通了

11 月 25 日，IBM Research 在 Hugging Face 博客发文，联合 Hugging Face 用开源 CUGA（ConfigUrable Generalist Agent）agent harness 做出一个面向印度语言的多语言语音助手原型。它要解决的缺口很具体：印度绝大多数数字化知识以英文存在，而多数人日常用印地语、泰米尔语、泰卢固语、古吉拉特语、马拉地语等交流，此前的数字助手基本只接受英文打字输入。演示场景是农业助手——用户用选定的印度语言口头发问，Agent 先把语音转文字，再用本地文档 embedding检索一本 154 页的英文农业手册，最后用用户的语言给出两到四句话的语音回答。技术上，CUGA 作为嵌入式 SDK 提供模型管理、工具编排与每个会话线程的状态隔离，可在 watsonx 与 OpenAI 之间切换；语音层解耦，可选用 Sarvam AI 云 API，也可用本地开源模型（SraVaani 做语音转文字、Svara 做文字转语音）。一个关键发现是：CUGA 默认的英文 embedding 无法为非英文查询检索到相关英文内容，团队因此换成 intfloat/multilingual-e5-large 多语言 embedding 模型。工程细节也做了：输出时剥掉 markdown 与引用让语音听起来自然，并加简单 guardrails 快速拦截离题问题。所有答案都基于检索到的、可核查的原文段落。代码与应用已开源，Hugging Face Spaces 可直接试用，另附开发者教程，并给出与 IBM Bharat Core AI 栈的集成路径。

Claude把Artifacts装成桌面应用：不打包不签名，能读本地文件

当地时间 11 月 24 日，Anthropic 宣布 Claude 推出「Install as app」（安装为应用）功能测试版，允许用户把 AI 生成的 Artifacts 直接安装为 Mac 或 Windows 桌面应用，无需手动打包、签名，也无需单独申请 API 密钥。安装后的应用有独立图标和运行窗口，可以像普通桌面软件一样打开，能调用 Claude 模型及用户已连接的外部服务，支持与他人共享，并在底层 Artifacts 内容被修改后自动更新。与网页环境下运行的 Artifacts 不同，安装后的应用获得更多系统交互能力：发送系统通知、在菜单栏或系统托盘添加图标、监听全局快捷键、创建置顶窗口；在获得完整电脑访问权限后，甚至可以运行程序、读取修改删除本地文件，无需逐次征得同意。Anthropic 展示了内部员工用它开发的多款应用，包括支持多图层操作的图像编辑器、文件管理器、自动整理文件的工具、内置 AI 助手的终端、监控电脑性能的系统工具。安全上设了三级权限：默认权限、应用权限、完整电脑访问权限；用户授予的权限仅对当前应用版本有效，每次更新后均需重新授权，即使更新由用户本人完成。Anthropic 同时提醒，公司不会在应用安装前进行审核，用户应仅向可信应用授予完整电脑访问权限。该功能正面向全套餐用户逐步开放测试，企业版需手动启用；应用仍需联网并登录 Claude 账号才能打开，调用模型消耗用户现有套餐额度；Claude Docs、Slides、Sheets 等部分 Artifacts 暂不支持安装。

关联洞察

趋势一：药学服务单独收费落地：医院药学部门从成本中心变成收入项

药品零加成之后，医院药学部长期处在一个尴尬位置：审方、调方、用药教育、血药浓度监测都是专业活，但没有对应的收费编码，人力成本只能摊进药事管理费里，越是认真做药学服务，科室越像纯支出。这次 4 类 10 项落地，等于给药学服务单独开了一本账。真正的意义不在于钱多钱少——药学门诊 6-16 元一次，比挂个专家号还便宜——而在于把「药师做了什么」变成可计价、可考核、可结算的项目。一旦有了价格编码，医院才有动力配药师、开药学门诊、建审方中心；医保才有依据把这些服务纳入支付；药师这个职业也才从「发药的」变成「提供服务的」。这是价格政策最典型的杠杆作用：先给一个名分，再谈给多少钱。

趋势二：6-16元的门诊费是引流价，真正的收入在配置费和中药服务

把价格表横着看会发现一个结构：药学门诊诊查费 6-16 元一次，副主任药师加收 5-10 元、主任药师加收 10-15 元，这个水平明显低于医生门诊，定位是低门槛铺量、先把患者引进来；而药品集中配置费（危害药品）30 元左右、肠外营养液配置费 35-40 元、放射性药物配置费单独立项，这些是按次计价的「操作型」项目，单价高、频次稳定、有明确临床必需性。中药侧更明显：中药配方颗粒调剂费 2-4 元/付，看起来单价低，但一付药一个计价单元，长期处方的复购频率极高；中药代煎、临方加工同样按付或按剂计。所以对医院来说，药学服务真正的收入盘子在配置类和中药类，门诊诊查更多是建立入口和认知。这也解释了为什么指南要专门配套中药配方颗粒零差率政策——零差率把药品加成砍掉了，调剂费是给中药房留的一条活路。

趋势三：普通静脉配置不再单收：这条边界比新增项目更值得读

指南里有一句容易被忽略的说明：普通静脉药物配置作为医院提供注射、输液时的应尽事项，已纳入相关「注射费」的价格构成，不再单独收费。这句话的分量不亚于新增的十个项目。它划出的是一条「什么是服务、什么是本分」的界线：配置普通输液是护理工作的组成部分，不能拆出来再收一遍钱；而配置危害药品（细胞毒性药物）需要生物安全柜、防护装备、专门废物处理，肠外营养液需要无菌配制和配比核算，这些超出常规操作的额外投入才配得上独立价格。这条边界对企业的含义很直接：任何想靠「拆分服务项」做增量的产品设计，都会撞上这条线。反过来，凡是能证明「这确实是超出常规的额外工作量」的场景——比如放射性药物、危害药品、居家上门——才是政策留出的空间。定价政策的本质从来不是给钱，而是定义什么算活儿。
